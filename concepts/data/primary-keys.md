## In one sentence

A primary key is the column (or columns) that uniquely identifies each row in a table.

## Analogy

Like a national ID number: two people can share a name and birthday, but never the ID.

## Why it matters

Without a unique identifier you can't reliably update, delete or reference a specific row. Other tables point to rows through their primary key.

## In code

```sql
CREATE TABLE todos (
  id    UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  title TEXT NOT NULL
);
```

Auto-increment integers are simple and compact; UUIDs can be generated anywhere (client, other services) and don't reveal how many rows exist.

## Common mistakes

- Using a mutable business value (email, name) as the primary key — when it changes, every reference breaks.
- Exposing sequential ids in public URLs, letting people guess other records.

## Good questions

- **Explain why**: Why is `id` generated by the database instead of using the todo's `title`?
- **What if**: What happens if two todos are inserted with the same `id`?
- **Choose**: Integer or UUID for this table — what would you pick and why?
